## v17 Windows 전용 실행 및 결함 수정
<!-- [NEW v17] 기존 안내는 이력이며, 현재 실행 방법은 이 섹션을 따른다. -->

Python 3.12 설치 후 압축을 일반 폴더에 풀고 **START_WINDOWS.bat**를 더블클릭한다. 최초 실행은 `.venv_windows_v17` 생성 → 패키지 설치 → 런타임 검사 → 서버 실행 순서다. 이후에는 런타임 검사 후 서버를 실행한다. 브라우저 주소는 http://127.0.0.1:8765/ 이다. 서버 창을 닫으면 서비스가 종료된다. 최초 설치에는 패키지를 내려받을 인터넷 연결이 필요하다. Linux/macOS 실행 파일은 v17 배포에서 제외했다. 기존 Windows v15 배치 파일은 호환용으로 보존하지만 새 단일 진입점을 사용한다.

설치 오류는 setup_windows_v17.log, 검사 결과는 runtime_check_v17.log에 기록한다. Numba/llvmlite import 및 간단한 JIT를 별도 프로세스에서 검사한다. 검사 비정상 종료·시간 초과 시 기존 계산식을 Python 함수로 실행한다. `CFRP_DISABLE_NUMBA=1`로 강제 전환할 수 있다. Python 경로는 느릴 수 있다. Windows 전용 포장 자체가 네이티브 충돌의 원인을 해결했다는 의미는 아니다.

`review_results(None, None)`은 blocked 판정을 반환한다. `run_ai(spec=...)`에도 자연어 근거 검사와 요청 Guard를 적용한다. API의 AI 실행·수동/실측 계산·연결 검사·검토 기록은 async_runtime_v17의 asyncio.to_thread 경로를 사용한다. 기존 동기 함수 호출 방식은 유지한다. async 프로그램에서는 `await run_ai_async(...)`를 사용한다. 전체 계산 결과의 예상 밖 None은 명시적 오류로 차단하고, 실측 요약의 cycle_time=None과 hold_end_DoC=None은 유지한다. Guard의 elif 분기를 독립 if로 변경했으며 물리 솔버의 단계 분기는 그대로다.

모델 소스 해시 변경 후 기존 입력 256건을 실제 재계산했다. 모든 수치 타깃의 최대 변화는 약 3.50e-12다. 합성데이터는 여전히 외부 실험으로 검증되지 않은 개발용이다.

## v18 Windows / Python 3.14 실행 기준
<!-- [NEW v18] 위의 3.12 안내는 과거 이력이다. 현재 버전은 이 섹션을 따른다. -->

**표준 64비트 CPython 3.14**를 설치하고, 새 폴더에 압축을 해제한 뒤 START_WINDOWS.bat를 실행한다. Python Launcher가 있으면 `py -3.14`를 선택하고, 없으면 `python`의 실제 버전을 검사한다. 실행 파일은 3.14만 허용한다. 자유 스레드 3.14t 및 32비트는 이 배포의 지원 대상이 아니다.

3.14 전용 가상환경은 `.venv_windows_py314_v18`이다. 기존 3.12 가상환경은 재사용하지 않는다. 현재 설치 파일은 `requirements-windows-py314-v18.txt`이며, pandas를 2.2.3에서 2.3.3으로 변경하고 llvmlite 0.50.0도 명시했다. 기존 requirements-html-v15.txt는 이력으로 보존하지만 현재 Windows 실행 파일은 사용하지 않는다. pip의 `--only-binary=:all:`로 소스 컴파일을 시도하지 않게 했다.

setup_windows_v18.log에는 설치 결과, runtime_check_v18.log에는 실제 Python 실행 경로·버전과 Numba 검사 결과가 기록된다. 기존 setup/run 배치 파일도 3.14 전용 설정으로 맞췄지만 기본 실행은 START_WINDOWS.bat 하나다.

3.12 강제 검사와 pandas 2.2.3의 cp314 Windows wheel 부재는 확인된 버전 불일치다. 이것이 사용자 컴퓨터의 Numba 비정상 종료 원인까지 입증하는 것은 아니다. Numba 격리 검사·Python fallback·Guard 수정·to_thread 호출 경로·실측 cycle_time=None 처리는 v17과 동일하다. 물리 계산 함수와 모델 해시는 변경하지 않았다.

현재 검증 결과 및 미완료 항목은 AUDIT_v18.md와 START_HERE_PY314_v18.md를 따른다.

## v19 결과 즉시 시각화
<!-- [NEW v19] 기존 내용은 보존하며 현재 화면 개선을 추가한다. -->

Windows 표준 64비트 Python 3.14 및 START_WINDOWS.bat 실행 방법은 v18과 같다. 의존성·가상환경 이름은 변경하지 않았다. 실행 중인 이전 서버 창을 종료하고 새 ZIP을 별도 폴더에 풀어 실행한다. 브라우저는 Ctrl+F5로 새로고침한다.

AI 답변 바로 아래의 **계산 결과 · 실시간 시각화**는 수동·AI·실측 결과의 검증된 series/field 배열로 자동 갱신한다. 온도·공기 대비 온도차·경화도 색상, CFRP 단면과 금형 온도, 온도/경화 이력, 시간×두께 온도장, 시간 슬라이더, 재생·최고온도 시점 버튼을 제공한다. SVG로 그리므로 3D WebGL 지원 없이 표시한다. 기존 시간 탐색·3D와 같은 저장 시점을 사용한다. 온도장 표시만 최대 120개 저장 시점으로 축소하고, 단면/수치/시간 이력은 원본 계산 배열을 사용한다.

폭이 작은 화면에서 Grid 자식이 Plotly 폭으로 늘어나는 문제를 억제했다. 후보가 없으면 빈 비교 그래프를 숨긴다. 3D Promise 거절·동기 예외·WebGL context loss에는 안내를 표시한다. 입력 변경/실행 실패 시 새 화면도 기존 결과 무효화 규칙을 따른다. 실측 cycle_time=None은 —로 유지한다.

## v20 물리 결과 → 3D 뷰어 연결
<!-- [NEW v20] 기존 설명은 보존하고 새 표시 경로만 추가한다. -->

새 ZIP을 별도 폴더에 풀고 기존 서버 창을 닫은 뒤 `START_WINDOWS.bat`를 실행한다. Windows 표준 64비트 Python 3.14 설치 경로와 의존성은 v18/v19와 동일하다. 브라우저는 Ctrl+F5로 새로고침한다.

AI 채팅 바로 아래 **물리 계산 결과 · 3D 공정 뷰어**가 추가됐다. 수동 계산·AI 추천·후보 선택·실측 재현이 기존 `renderCharts(result)`를 호출하면 새 `viz3d_live_v20.js`도 같은 결과를 받는다. 입력은 기존 검증 결과의 condition/options/summary/series/field/run_id_v14이다. 별도 물리 공식이나 LLM 답변 숫자를 시각화에 사용하지 않는다. 수동 입력 → Physics → 배열 검증 → 결과 → 화면, AI → 후보조건 → Physics 재실행 → Guard → 결과 → 화면 경로를 유지한다. Guard 통과는 내부 소프트웨어 검사이며 외부 실험 정확도를 뜻하지 않는다.

KPI, 3D 안의 현재 시간·공기/중앙 온도·공기 대비 차이·최저 경화도, A 하면/B 중앙/C 상면 수치, 온도/공기 대비 온도차/경화도 색상, 최고온도 시점, 처음부터/이어서 재생·정지와 시간 슬라이더를 제공한다. 새 결과는 기존 프레임을 purge하고 newPlot/addFrames로 재생성한다. 최대 60개 원본 저장 시점을 사용하며 선택안의 실제 저장 최고온도 시점을 포함한다. 보간이나 온도 재계산은 없다. AI 기준안과 선택안은 같은 시간축과 색 범위로 나란히 그리며 먼저 끝난 쪽은 마지막 저장 상태를 유지한다. 선택안이 바뀌면 같은 렌더러를 다시 실행한다. 새 뷰어의 슬라이더는 두 3D를 함께 움직이며 기존 상세 탐색 슬라이더는 독립적으로 유지된다.

기존 runGenerationV14/입력 스냅샷 및 채팅 revision 검사 뒤 게시된 latest만 받는다. 뷰어도 revision으로 지연된 Plotly 작업을 폐기한다. 입력 무효화 시 재생을 정지하고 기존 결과를 비운다. 실측 cycle_time=null은 —로 표시한다. WebGL 실패 시 기존 SVG 단면 안내를 제공한다.

앞선 대화의 cut 결함 판정은 정정한다. 기존 z_part는 상면 기준 깊이이며 compVals는 reverse로 금형부터 쌓인다. 선택 셀 cell 이상(선택 셀 및 그 아래)을 남기는 기존 nz-cell개의 셀과 금형부터 시작하는 geometry는 서로 대응한다. cell offset을 추가하면 오히려 위치가 어긋나므로 stack_view_v14.js를 수정하지 않았다. core.py/AI.py/AI_guard.py도 변경하지 않았다.

## v22 demo 3D 시각화 이식 및 오른쪽 스크롤바
<!-- [NEW v22] 기존 내용은 이력으로 유지한다. -->

첨부 viz3d_demo (1)(2).html의 3D 표시 구성을 v21의 **3D 공정** 화면으로 이식했다. demo의 고정 예시 계산값은 가져오지 않는다. 기존 검증 결과의 series/field/condition/options를 사용하며, 각 셀의 색은 실제 온도·공기 대비 온도차·경화도 값에 대응한다. 단면의 색 차이가 드러나도록 기본 색상은 **공기 대비 ΔT**다. 셀 온도가 같으면 색도 같으며 보기 좋게 만들기 위한 임의 색이나 물리값 보간을 넣지 않는다.

## v23 물리모델 대리학습 및 Agent 자동 로드

## [NEW v34r2] 제출용 실행방법 · 보안 · 출처 최종 안내
<!-- [NEW v34r2] 기존 개발 이력은 수정하지 않고 현재 제출 기준을 끝에 추가한다. -->

현재 제출본은 **Windows 표준 64비트 CPython 3.14** 기준이다. 기존 README 상단의 v16/v17/v15 안내는 개발 이력이며 현재 실행 기준이 아니다.

1. ZIP을 일반 폴더에 완전히 압축 해제한다. ZIP 내부에서 직접 실행하지 않는다.
2. 표준 64비트 Python 3.14를 설치한다. Python Launcher(`py`) 사용을 권장한다.
3. 프로젝트 최상위의 `START_WINDOWS.bat`를 더블클릭한다.
4. 최초 실행 시 `.venv_windows_py314_v18` 생성 → `requirements-windows-py314-v18.txt` 설치 → 런타임 검사 → 서버 실행 순으로 진행된다. 최초 설치에는 인터넷 연결이 필요하다.
5. 브라우저가 자동으로 열리지 않으면 `http://127.0.0.1:8765/`에 접속한다. 서버 콘솔 창은 닫지 않는다.
6. 수동 Physics 계산은 Ollama 없이 가능하다. 자연어 Agent를 사용하려면 별도 Ollama 설치 후 `gemma2` 또는 설정된 Qwen3 모델을 내려받아 Ollama 서버를 실행한다.
7. 모델 재학습은 필요 없다. 3,000건 학습 완료 저장모델이 포함되어 있다.
8. 기존 서버가 실행 중이었다면 종료한 후 새 폴더에서 실행하고 브라우저는 `Ctrl+F5`로 새로고침한다.

제출용 출처·AI 활용·합성데이터·기존자산/신규개발분·보안 점검 결과는 `docs/SOURCES_AND_DISCLOSURE_v34r2.md`를 따른다. 과거 테스트 로그의 로컬 Windows 사용자 경로 2건은 비식별화했으며, API Key/비밀번호/개인키 파일은 정적 검사에서 발견되지 않았다. 기능·물리식·저장 대리모델은 이번 제출 정리에서 변경하지 않았다.
