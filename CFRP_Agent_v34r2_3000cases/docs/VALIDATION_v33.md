# CFRP v33 자연어 해석·검증 수정 결과

기존 Studio Refined ZIP에 독립 요청 해석 모듈을 연결했습니다. UI·스킨·물리 계산·최적화 공식·700개 데이터·저장 모델은 보존했습니다. AI가 만든 잘못된 숫자나 범위를 자동 덮어써 통과시키지 않고, 요청과 대조해 거부하거나 기존 한도 안에서 JSON 재시도를 수행합니다.

## 변경 내용

- 목표 별칭, 공동 단계, 단계별 유지시간 및 명시 단위 변환을 정규화합니다.
- 제약 방향을 검사합니다. 온도 상한·경화도 하한과 반대 방향 및 엄격한 미만/초과는 설명과 함께 확인합니다.
- 변경 변수와 고정 변수를 분리하고 정확한 탐색 집합을 대조합니다.
- 지원 밖 재료·형상·옵션, 재료 오타, 검증 생략 지시를 차단합니다.
- 현재 요청에서 얻은 독립 근거를 AI에 제공하고, 숫자·목표·변수 오류를 제한된 재시도에 전달합니다. 화면 기준값을 프롬프트에 복사하지 않습니다.
- 요청별 JSON 스키마에 독립적으로 확인된 작업·목표·정규 단위·허용 필드·탐색 범위를 제한합니다. 모델 반환값은 사후 덮어쓰지 않고 다시 검증합니다.

## 남은 표현과 검증 한계

| 항목 | 상태 |
|---|---|
| 콜론 시간 `01:30` | 분/시간 구분이 없는 입력은 확인 요청. `90분`으로 지정 필요 |
| 이전 값→새 값, 같은 시간, 상대 온도 | 각 단계 최종 수치를 명시하도록 확인 요청. 기존 기대값을 바꾸지 않고 아래 실패 목록에 유지 |
| Windows Python 3.14 지정 환경 | 접근 제한으로 실제 실행 미검증. 이번 실행은 Windows Python 3.12.14 |
| 사용자 GPU·창 겹침·빈 배열 API | 이번 요청 해석 수정 범위 밖. 이전 검토 문제를 해결했다고 주장하지 않음 |
| 외부 실험 정확도 | 미검증. 합성 물리 모델의 소프트웨어 시험 |

- C0374: 1차 유지시간 01:30 계산해줘 → 시간 콜론 표기는 모호합니다. 90분처럼 단위를 명시하십시오.; 단계/변수에 연결되지 않은 숫자가 있습니다. 각 변수의 최종 값을 명시하십시오.; hold1: 요청의 값/단위와 AI 적용값이 일치하지 않습니다. 명시하지 않은 숫자를 추가할 수 없습니다.

평가에서 search_variables=[]는 설정의 기본 6개 변수를 뜻하므로 동일한 6개를 명시한 출력과 같은 실효 범위로 비교했습니다. 이 표기 차이를 오해석으로 센 2건의 판정만 보정했고, 모델 원문과 최초 판정도 JSON에 보존했습니다. 수치 비교 허용 오차는 1e-6입니다.

실제 모델 시험은 Gemma2와 설치된 `qwen3:latest`를 사용했습니다. Qwen3 프로필의 `qwen3:8b` 태그는 변경하지 않았으며 동일 태그 실행을 보장하지 않습니다. 수정 전 시험은 JSON 재시도 0회였고 이번 시험은 기본 1회를 사용하므로 모델 전후 비교에는 이 조건 차이를 고려해야 합니다. 일부 확인 요청은 독립 사전 검증에서 끝나 모델을 호출하지 않습니다. 위 실제 호출 수는 이벤트 기준으로 별도 집계했습니다.

| 실제 모델 | 요청 흐름 수 | 기대 일치 | 확인 대상 오통과 | 오류 |
|---|---:|---:|---:|---:|
| gemma2 | 2 | 2 | 0 | 0 |
| qwen3 | 26 | 26 | 0 | 0 |
